# Analytics Pro

Рабочая основа демонстрационной CRM: Next.js App Router, React, TypeScript,
Tailwind, Radix Dialog, Recharts, Motion, Prisma и PostgreSQL.
Исходный статический эксперимент сохранён в `src/`, `index.html` и `tools/`;
новое приложение использует `app/`, `components/` и `lib/`.

## Реализовано

- Отдельная серверная демосессия на 24 часа через случайный HttpOnly cookie.
- Создание аккаунтов, изменение этапа, передача в медиабаинг, поиск, история лимитов.
- Настройка имён ответственных в пределах демосессии и журналирование изменений.
- Аналитика фарма: funnel, связки proxy/BIN/схема прогрева и корреляции банов.
- Доходы и расходы в целых центах; расчёт прибыли и ROI, график операций.
- Сводки по правилам, не имитация ответов подключённого AI.
- Серверная валидация Zod и проверка принадлежности каждой записи сессии.
- Переключение трёх ранних визуальных концепций.

Все данные вымышлены. Google Ads, банковские сервисы и AI не подключены.
Это не production CRM и не система рекламной автоматизации.

## Локальная разработка

Node 22, Docker Compose (или собственный PostgreSQL 16).

1. Установить `DEMO_DB_PASSWORD` в окружении, запустить
   `docker compose -p analytics-pro-demo -f compose.demo.yml up -d`.
2. Создать локальный `.env` с `DATABASE_URL` для отдельной базы
   `analytics_demo` на `127.0.0.1:15432`. Не использовать базу старого проекта.
3. `npm ci`, `npx prisma generate`, `npm run db:migrate`, `npm run dev`.
4. Открыть http://127.0.0.1:14001.

`npm test` — расчёты и валидация. `npm run build` — production-сборка и типы.
`npx playwright install chromium`, `npm run test:e2e` — тест сохранения и
изоляции двух посетителей, требуется доступная база с миграциями.

## Ограничения перед публичным запуском

Нужны HTTPS (production cookie Secure), ограничение создания сессий на reverse
proxy, плановая очистка истёкших Workspace, наблюдаемость и проверка восстановления.
Лимиты одной сессии: 100 аккаунтов и 200 операций. Создание новых сессий пока не
ограничено глобально. Не публиковать приложение без rate limiting и очистки базы.
Серверный origin должен сохраняться reverse proxy; запросы изменения проверяют Origin.
CI использует отдельную временную PostgreSQL. Автоматического деплоя нет.

Prisma 6 использует override `deepmerge-ts@8.0.0` для устранения опубликованного
advisory в инструменте конфигурации; generate/build проверяются с этим override.
Полноценная ролевая модель, подключение внешнего AI и кампании как отдельные
сущности пока не реализованы. Журнал фиксирует финансовые действия, создание
аккаунтов, смены статуса и изменения лимитов.
